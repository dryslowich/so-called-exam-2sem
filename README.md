# ЧАСТЬ I. УЧЕБНИК

## 1. Парадигма ООП: четыре принципа

Объектно-ориентированное программирование строится вокруг понятия **объекта** — сущности, объединяющей данные (состояние) и поведение (методы). Четыре фундаментальных принципа:

- **Инкапсуляция** — объединение данных и методов в единый тип и сокрытие внутреннего устройства за интерфейсом.
- **Наследование** — построение новых классов на основе существующих с повторным использованием и расширением их функциональности.
- **Полиморфизм** — возможность работать с объектами разных типов через единый интерфейс; конкретное поведение определяется фактическим типом объекта.
- **Абстракция** — выделение существенных характеристик объекта и игнорирование несущественных; описание сущности через её интерфейс, а не реализацию.

Эти принципы взаимосвязаны: абстракция задаёт интерфейс, инкапсуляция его защищает, наследование позволяет переиспользовать, полиморфизм — единообразно использовать. Покажем их на одном сквозном примере, к которому ещё вернёмся:

```cpp
#include <iostream>
#include <string>

// Абстракция + инкапсуляция: класс описывает "что умеет" объект,
// скрывая "как именно" он это делает.
class Account {
    std::string owner;   // private по умолчанию — скрытое состояние
    double balance;
public:
    Account(const std::string& owner, double start)
        : owner(owner), balance(start) {}

    void deposit(double sum) {        // интерфейс: пополнение
        if (sum > 0) {
            balance += sum;
        }
    }

    virtual void print() const {      // virtual — задел под полиморфизм
        std::cout << owner << ": " << balance << '\n';
    }
};

// Наследование: SavingsAccount "является" Account и добавляет специфику.
class SavingsAccount : public Account {
    double rate;
public:
    SavingsAccount(const std::string& owner, double start, double rate)
        : Account(owner, start), rate(rate) {}

    void print() const override {     // полиморфизм: своё поведение
        Account::print();
        std::cout << "  (savings, rate " << rate << ")\n";
    }
};

int main() {
    Account a("Anna", 100.0);
    SavingsAccount s("Boris", 500.0, 0.05);

    Account* items[] = { &a, &s };    // работаем через общий интерфейс
    for (Account* p : items) {
        p->print();                   // вызовется нужная версия print()
    }
}
```

## 2. Класс и объект. Инкапсуляция

**Класс** — это пользовательский тип данных, описывающий устройство объектов: какие у них поля и какие операции над ними допустимы. **Объект** — конкретный экземпляр класса, занимающий память.

```cpp
class Point {
    int x;             // поле (член-данные)
    int y;
public:
    void set(int nx, int ny) {   // метод (член-функция)
        x = nx;
        y = ny;
    }
    int getX() const { return x; }
    int getY() const { return y; }
};

int main() {
    Point p;           // объект — экземпляр класса
    p.set(3, 4);
    Point q = p;       // ещё один объект (копия p)

    std::cout << p.getX();   // 3
    // p.x = 10;             // ✗ ошибка: x private, снаружи недоступен
}
```

**Инкапсуляция** как принцип проявляется в трёх взаимодополняющих смыслах:

- **объединение** данных и функций для работы с ними в одном типе;
- **скрытие подробностей реализации** пользовательского типа — снаружи виден только интерфейс (публичные методы), а внутреннее устройство закрыто;
- **изоляция** пользователя объекта от его внутреннего устройства — клиент не зависит от того, как именно хранятся данные.

Инкапсуляцию **не** следует путать с наследованием: «расширение свойств класса дополнительными» — это про наследование, а не про инкапсуляцию.

**Зачем нужна.** Сокрытие позволяет менять реализацию класса, не затрагивая код, который им пользуется, и гарантировать инварианты. Пример — класс хранит дробь и поддерживает инвариант «знаменатель не равен нулю»:

```cpp
class Fraction {
    int num;           // числитель
    int den;           // знаменатель — инвариант: den != 0
public:
    Fraction(int n, int d) {
        num = n;
        den = (d == 0) ? 1 : d;   // защищаем инвариант в одном месте
    }

    double value() const {
        return static_cast<double>(num) / den;   // деление на 0 невозможно
    }
};
```

Снаружи нельзя присвоить `den = 0` напрямую — поле закрыто, а все пути изменения проходят через методы, которые поддерживают инвариант.

## 3. Класс vs структура. Модификаторы доступа

В C++ есть три модификатора доступа:

- **`public`** — члены доступны откуда угодно;
- **`protected`** — доступны внутри класса и в производных классах (и их друзьях);
- **`private`** — доступны только внутри самого класса (и его друзей).

```cpp
class Widget {
public:
    int pub;        // доступен всем
protected:
    int prot;       // доступен в Widget и его наследниках
private:
    int priv;       // доступен только в Widget (и friend)
};

class Derived : public Widget {
    void f() {
        pub  = 1;   // ✓
        prot = 2;   // ✓ — protected доступен в наследнике
        // priv = 3; // ✗ — private базового недоступен наследнику
    }
};

int main() {
    Widget w;
    w.pub = 1;      // ✓
    // w.prot = 2;  // ✗ снаружи
    // w.priv = 3;  // ✗ снаружи
}
```

**Единственное реальное отличие `class` от `struct` в C++** — доступ по умолчанию: в `class` члены по умолчанию `private`, в `struct` — `public`. По умолчанию `struct` также наследуется публично, а `class` — приватно. В остальном это одно и то же:

```cpp
struct S {          // по умолчанию public
    int x;          // public
    void f();       // public
};

class C {           // по умолчанию private
    int x;          // private
    void f();       // private
};

// Эти два объявления эквивалентны:
struct S2 { private: int x; public: void f(); };
class  C2 {         int x; public: void f(); };
```

**Отличие от языка Си важно различать.** Структура **языка Си** — это просто набор данных, она не может содержать методы. Когда в вопросе сравнивают «класс C++ и структуру Си», правильно: класс C++ содержит и данные, и методы; структура Си — только данные.

**Что компилятор узнаёт из объявления класса:** ограничения доступа к членам; значения параметров по умолчанию; размер объекта (по составу полей и наличию `vptr`); прототипы методов. Объявление класса **не** содержит инициализацию глобальных переменных.

**Что может содержать тело класса:** объявления полей, прототипы методов, inline-реализации методов прямо в теле, вложенные типы, static-члены, друзей.

```cpp
class Demo {
    int field;                       // объявление поля
    static int counter;              // static-член (определяется в .cpp)

public:
    void declared(int);              // прототип — реализация в .cpp

    int inlineMethod() const {       // inline-реализация прямо в теле
        return field;
    }

    class Helper { /* ... */ };      // вложенный тип

    friend void debug(const Demo&);  // друг
};
```

## 4. Поля и методы. Указатель this

Внутри нестатического метода доступен неявный указатель **`this`** — адрес объекта, для которого вызван метод.

```cpp
class A {
    int m_a;
public:
    void f(int m_a) {          // параметр затеняет поле m_a
        this->m_a = m_a;       // слева — поле объекта (this->m_a), справа — параметр
    }
};
```

Поскольку `this` — это **указатель**, обращение к полю идёт через `->` (или `(*this).`), но **не** через `this.`:

```cpp
class A {
    int m_a;
public:
    void g() {
        this->m_a = 5;    // ✓ через указатель
        (*this).m_a = 5;  // ✓ разыменование, потом точка
        // this.m_a = 5;  // ✗ this — указатель, точка к нему неприменима
    }
};
```

**Три способа обратиться к полю текущего объекта внутри метода** — `m_a`, `this->m_a` и `A::m_a`. Важно понимать про последний: **`A::m_a` — это квалифицированное имя**, и оно работает не только со статическими полями. Внутри нестатического метода `A::m_a` означает «член `m_a` из области видимости класса `A`», применённый к текущему объекту (`this`). То есть `A::m_a` внутри метода эквивалентно `this->A::m_a` — экземпляр не указывается явно, потому что подразумевается `this`.

```cpp
class A {
    int m_a;
public:
    void f(int m_a) {
        m_a       = m_a;   // присваивание параметра самому себе — поле НЕ меняется
        this->m_a = m_a;   // ✓ поле текущего объекта = параметр
        A::m_a    = m_a;   // ✓ то же самое: A::m_a внутри метода — поле текущего объекта
    }
};
```

Где интуиция «`A::` — это только про статику» **верна**: квалификацию `A::m_a` нельзя использовать **вне метода без объекта**. Тогда она работала бы лишь для статического члена:

```cpp
class A {
    int m_a;            // нестатическое поле
    static int s_cnt;   // статическое поле
public:
    void method() {
        A::m_a = 1;     // ✓ есть this — обращение к полю текущего объекта
    }
};

int A::s_cnt = 0;

int main() {
    A::s_cnt = 5;       // ✓ статическое поле не привязано к объекту
    // A::m_a = 5;      // ✗ ошибка: нет объекта, к которому относится m_a

    A obj;
    obj.A::m_a = 5;     // ✓ так можно: явная квалификация поля КОНКРЕТНОГО объекта
}
```

Итого:

- `A::m_a` **внутри** нестатического метода `A` — обращение к полю текущего объекта (через неявный `this`).
- `A::m_a` **вне** метода без объекта — корректно только для статического члена.
- `obj.A::m_a` — обращение к полю конкретного объекта `obj` с явной квалификацией класса (нужно, например, при неоднозначности имён в иерархии наследования).

Зачем вообще квалифицировать нестатическое поле через `A::`? Чтобы снять неоднозначность — когда параметр затеняет поле (пример выше) или когда у базового и производного классов есть одноимённые члены:

```cpp
class Base {
protected:
    int value = 1;
};

class Derived : public Base {
    int value = 2;     // затеняет Base::value
public:
    int sum() const {
        return value + Base::value;   // 2 + 1: своё поле и поле базового
    }
};
```

## 5. Размер объекта: sizeof и выравнивание

`sizeof(объект)` определяется составом нестатических полей с учётом:

- **выравнивания (alignment):** каждое поле размещается по адресу, кратному его размеру; между полями и в конце объекта возможны байты-заполнители (**padding**);
- **указателя на таблицу виртуальных функций (`vptr`):** добавляется, если в классе есть хотя бы одна виртуальная функция (обычно 8 байт на 64-битной платформе);
- **пустого класса:** `sizeof` пустого класса равен **1** (минимум, чтобы у разных объектов были разные адреса).

Методы (и inline, и не-inline) и static-поля **в объект не входят** — память под код и под статические данные выделяется отдельно, один раз.

**Пример с выравниванием.** Порядок полей влияет на размер из-за padding:

```cpp
struct Bad {
    char  a;    // 1 байт
    // 3 байта padding, чтобы int встал по адресу, кратному 4
    int   b;    // 4 байта
    char  c;    // 1 байт
    // 3 байта padding в конце (для выравнивания массива таких структур)
};  // sizeof(Bad) == 12

struct Good {
    int   b;    // 4 байта
    char  a;    // 1 байт
    char  c;    // 1 байт
    // 2 байта padding
};  // sizeof(Good) == 8
```

**Пример с пустым классом и vptr:**

```cpp
class Empty {};                  // sizeof == 1

class WithBool {
    bool b;                      // 1
    int  x;                      // 1(bool) + 3(padding) + 4(int)
};                               // sizeof == 8

class Virtual {
    double d;                    // 8
public:
    virtual void f();            // наличие virtual → добавляется vptr (8)
};                               // sizeof == 16 (vptr 8 + double 8)
```

**Вложенный объект** занимает место как самостоятельный — его размер целиком входит в размер охватывающего класса:

```cpp
class A {
    double m_a;                  // 8
public:
    A(double a = 0);
    virtual void f();            // virtual → vptr 8
};                               // sizeof(A) == 16

class B {
    double m_b;                  // 8
    A      m_A;                  // sizeof(A) == 16
public:
    B(double a, double b);
};                               // sizeof(B) == 8 + 16 == 24
```

Если убрать `virtual` из `A`, то `sizeof(A) == 8` (только `double`), и тогда `sizeof(B) == 8 + 8 == 16`. Это отличие — частый вопрос на экзамене: ищите слово `virtual` в базовом/вложенном классе.

## 6. Конструкторы

**Конструктор** — специальный метод, автоматически вызываемый при создании объекта; его задача — привести объект в корректное начальное состояние. Свойства:

- имя совпадает с именем класса, возвращаемого типа нет;
- **может** иметь параметры, в том числе со значениями по умолчанию;
- **может** выполнять любые инициализирующие действия — не только присваивание полей, но и вызовы функций, выделение ресурсов, проверки;
- может быть несколько (перегрузка).

```cpp
class Vector {
    int* data;
    int  size;
public:
    Vector() {                        // конструктор по умолчанию
        data = nullptr;
        size = 0;
    }

    Vector(int n) {                   // конструктор с параметром
        size = n;
        data = new int[n];            // нетривиальное действие: выделение памяти
        for (int i = 0; i < n; ++i) {
            data[i] = 0;              // и вызов цикла — это допустимо
        }
    }
};
```

**Виды конструкторов:**

- **по умолчанию** — вызывается без аргументов (`A()` или конструктор, все параметры которого имеют значения по умолчанию);
- **с параметрами** — `A(int)`, `A(double, double)` и т. п.;
- **копирования** — `A(const A&)` (см. раздел 9);
- **перемещения** — `A(A&&)` (см. раздел 11).

**`explicit`** запрещает использовать конструктор для неявных преобразований:

```cpp
class A {
public:
    explicit A(int x) { /* ... */ }
};

void use(A obj);

int main() {
    A a1(1);       // ✓ прямая инициализация
    A a2{1};       // ✓ прямая инициализация (списком)
    // A a3 = 1;   // ✗ копирующая инициализация запрещена explicit
    // use(1);     // ✗ неявное преобразование int -> A запрещено
    use(A(1));     // ✓ явное преобразование
}
```

Без `explicit` строка `A a3 = 1;` означала бы неявное `A a3 = A(1);` — иногда удобно, иногда опасно (случайные преобразования). `explicit` отключает эту неявность.

**Создание объектов и вызовы конструкторов:**

```cpp
class A {
public:
    A();           // по умолчанию
    A(int);        // с аргументом
};

void demo() {
    A a;                    // конструктор по умолчанию
    A b(5);                 //конструктор с аргументом
    A c{5};                 // он же (фигурные скобки)

    A* p1 = new A;          // в куче, конструктор по умолчанию
    A* p2 = new A(5);       // в куче, с аргументом
    A* arr1 = new A[10];    // массив из 10 объектов: A() вызывается 10 раз

    A* arr2[5];             // массив из 5 УКАЗАТЕЛЕЙ — объекты НЕ создаются,
                            // конструкторы НЕ вызываются (указатели не инициализированы)

    delete p1;
    delete p2;
    delete[] arr1;
}
```

Число и типы аргументов должны соответствовать какому-либо конструктору. Запись `int qwe(33);` внутри функции — это **прямая инициализация переменной** `qwe` значением 33, а не вызов функции и не прототип:

```cpp
int main() {
    int qwe(33);            // то же, что int qwe = 33;
    int zero{};             // инициализация нулём
    // int f(int);          // а ВОТ ЭТО на уровне файла было бы прототипом функции
}
```

**Если конструкторов не объявлено,** компилятор генерирует конструктор по умолчанию. Но как только объявлен **любой** пользовательский конструктор, конструктор по умолчанию автоматически не создаётся:

```cpp
class A {
public:
    A(int x) {}        // объявлен пользовательский конструктор
};

int main() {
    A a(5);            // ✓
    // A b;            // ✗ конструктора по умолчанию нет — компилятор его не создал
}
```

## 7. Список инициализации

Поля и базовый класс предпочтительно инициализировать в **списке инициализации** конструктора, а не присваиванием в теле:

```cpp
class Point {
    int x;
    int y;
public:
    Point(int nx, int ny)
        : x(nx), y(ny)        // список инициализации
    {
        // тело: дополнительные действия, если нужны
    }
};
```

**Почему это важно:**

**1. Эффективность.** Поле сразу строится нужным значением. При инициализации в теле поле сначала создаётся конструктором по умолчанию, а затем перезаписывается присваиванием — двойная работа:

```cpp
#include <string>

class Person {
    std::string name;
public:
    // Плохо: name сначала создаётся пустой, потом присваивается
    Person(const std::string& n) {
        name = n;             // конструктор по умолчанию + operator=
    }

    // Хорошо: name сразу строится из n
    Person(const std::string& n)
        : name(n)             // один вызов конструктора копирования
    {}
};
```

**2. Базовый класс** инициализируется только через вызов его конструктора в списке. Поле базового класса (особенно `private`) **нельзя** инициализировать в производном напрямую — лишь через конструктор базового:

```cpp
class A {
    int m_a;                  // private
public:
    A(int a) : m_a(a) {}      // у A нет конструктора по умолчанию!
};

class B : public A {
    int m_b;
public:
    // ✓ правильно: базовый класс инициализируется вызовом A(a) в списке
    B(int a, int b)
        : A(a), m_b(b)
    {}

    // ✗ так нельзя:
    // B(int a, int b) { m_a = a; m_b = b; }   // m_a private и недоступен;
    //                                          // к тому же A не имеет конструктора
    //                                          // по умолчанию для неявного вызова
};
```

**3. Обязательность.** `const`-поля и поля-ссылки можно инициализировать **только** в списке (присваивание в теле для них невозможно):

```cpp
class Config {
    const int id;             // const-поле
    int& ref;                 // поле-ссылка
public:
    Config(int i, int& r)
        : id(i), ref(r)       // только так — в теле присвоить уже нельзя
    {}
};
```

**Порядок инициализации** определяется порядком **объявления полей** в классе, а не порядком в списке инициализации. Это источник коварных ошибок:

```cpp
class Bad {
    int b;
    int a;
public:
    // В списке сначала написано a(x), потом b(a),
    // НО инициализируются они в порядке ОБЪЯВЛЕНИЯ: сначала b, потом a.
    // Значит b(a) использует ещё не инициализированное a — мусор!
    Bad(int x)
        : a(x), b(a)          // опасно: b получит мусор
    {}
};
```

## 8. Деструктор

**Деструктор** `~A()` вызывается при уничтожении объекта; его задача — освободить ресурсы (память, файлы, соединения). Свойства:

- имя — `~ИмяКласса`, без параметров и без возвращаемого типа;
- класс имеет ровно один деструктор;
- вызывается **автоматически**.

```cpp
class Buffer {
    int* data;
public:
    Buffer(int n) {
        data = new int[n];        // захват ресурса в конструкторе
    }

    ~Buffer() {
        delete[] data;            // освобождение ресурса в деструкторе
    }
};
```

**Когда вызывается:**

- для локального объекта — при выходе из **блока**, в котором он объявлен (по закрывающей `}` этого блока, а не функции);
- для объекта в куче — при `delete`;
- для глобальных/`static` — при завершении программы;
- для полей-объектов и базовой части — автоматически после тела деструктора, в порядке, **обратном** конструированию.

```cpp
void Func() {
    Buffer outer(10);             // (1) создан outer

    {
        Buffer inner(5);          // (2) создан inner
    }                             // (3) ~inner() — на выходе из ВНУТРЕННЕГО блока

    // ... здесь inner уже уничтожен, outer ещё жив ...

}                                 // (4) ~outer() — на выходе из функции
```

Порядок: создаются `outer`, затем `inner`; уничтожаются в обратном порядке, но `inner` — раньше, потому что его блок закрывается раньше.

**Когда нужно писать деструктор явно:** когда объект владеет ресурсом, требующим освобождения (динамическая память, дескрипторы), в том числе при специфических действиях в производных классах. Для простого класса без ресурсов сгенерированного деструктора достаточно:

```cpp
class Plain {
    int x;
    double y;
    // деструктор не нужен — нет ресурсов, сгенерированный справится
};

class Owner {
    int* data;
public:
    Owner()  { data = new int[100]; }
    ~Owner() { delete[] data; }    // нужен явно — иначе утечка памяти
};
```

## 9. Конструктор копирования

**Конструктор копирования** создаёт новый объект как копию существующего.

**Корректные прототипы:**

```cpp
class A {
public:
    A(const A&);   // канонический
    // A(A&);      // тоже допустимо, но реже используется
};
```

**Недопустимо:**

```cpp
class A {
public:
    A(A);              // ✗ приём по значению вызвал бы сам себя → бесконечная рекурсия
    A(const A&) const; // ✗ конструктор не может быть const
};
```

**Когда вызывается** — разберём на конкретных строках:

```cpp
class A { /* ... */ };

void byValue(A obj);     // принимает по значению
A    makeA();            // возвращает по значению

void demo() {
    A a;

    A b(a);              // ① инициализация нового объекта существующим
    A c = a;             // ② то же самое (это НЕ присваивание, а инициализация)
    A* p = new A(a);     // ③ копия в куче

    byValue(a);          // ④ передача по значению → копируется в параметр
    A d = makeA();       // ⑤ возврат по значению → конструктор копирования
                         //    (часто устраняется оптимизацией RVO)
}
```

**Когда НЕ вызывается:**

```cpp
void byRef(A& obj);      // по ссылке — копии нет
void byPtr(A* obj);      // по указателю — копии нет

void demo2() {
    A a1;
    A a2;
    a2 = a1;             // ⑥ это operator= (присваивание), а НЕ конструктор копирования —
                         //    объект a2 уже существует

    byRef(a1);           // ⑦ копии нет
    byPtr(&a1);          // ⑧ копии нет
}
```

**Когда писать явно.** Сгенерированный конструктор копирует поля побитово (поверхностное копирование). Если в классе есть указатель на динамическую память, побитовая копия приведёт к тому, что два объекта будут владеть одной областью → двойное освобождение при разрушении и порча данных. Нужен **глубокий** копирующий конструктор:

```cpp
class String {
    char* data;
    int   len;
public:
    String(const char* s) {
        len  = std::strlen(s);
        data = new char[len + 1];
        std::strcpy(data, s);
    }

    // Глубокое копирование: выделяем СВОЮ память и копируем содержимое
    String(const String& other) {
        len  = other.len;
        data = new char[len + 1];      // отдельный буфер
        std::strcpy(data, other.data);
    }

    ~String() { delete[] data; }
};

// Без явного конструктора копирования:
//   String a("hi");
//   String b = a;        // b.data == a.data (один и тот же указатель!)
//   // при разрушении: delete[] вызовется дважды для одного буфера → крах
```

Само по себе наличие константных полей или виртуальных методов явного копирующего конструктора **не** требует — причина именно во владении ресурсами.

## 10. Оператор присваивания

**`operator=`** присваивает одному уже существующему объекту значение другого.

**Эффективная сигнатура** — возвращать **ссылку** на объект:

```cpp
class A {
public:
    A& operator=(const A&);   // ✓ эффективно: без лишней копии, поддерживает a = b = c
    // A operator=(const A&); // менее эффективно: возврат по значению создаёт лишнюю копию
};
```

Возврат по ссылке нужен, чтобы работала цепочка присваиваний и не возникало лишнего копирования результата:

```cpp
A a, b, c;
a = b = c;          // разбирается как a = (b = c);
                    // (b = c) должно вернуть ссылку на b, чтобы присвоить её в a
```

**Автоматически сгенерированный `operator=`:**

- поэлементно копирует поля встроенных типов;
- для полей-объектов вызывает их `operator=`;
- вызывает `operator=` базового класса.

Деструкторы он при этом не вызывает.

**Канонический вид** (с защитой от самоприсваивания и возвратом `*this`):

```cpp
class String {
    char* data;
    int   len;
public:
    String& operator=(const String& other) {
        if (this != &other) {          // защита от самоприсваивания (a = a)
            delete[] data;             // освобождаем старый ресурс
            len  = other.len;
            data = new char[len + 1];  // выделяем новый
            std::strcpy(data, other.data);
        }
        return *this;                  // возвращаем себя для цепочки
    }
};
```

**Вызов `operator=` базового класса из производного.** Когда `B : public A` реализует свой `operator=`, базовую часть присваивают так:

```cpp
class A {
    int m_a;
public:
    A& operator=(const A&);
};

class B : public A {
    int m_b;
public:
    B& operator=(const B& other) {
        // Вариант 1: привести себя к базовому типу и присвоить
        static_cast<A&>(*this) = other;     // ✓ вызовет A::operator=

        // Вариант 2 (эквивалент): явный вызов оператора базового класса
        // this->A::operator=(other);       // ✓

        m_b = other.m_b;                     // затем присваиваем свои поля
        return *this;
    }
};
```

**Ошибка — бесконечная рекурсия** (оператор вызывает сам себя):

```cpp
B& B::operator=(const B& other) {
    this->operator=(other);   // ✗ это снова B::operator= → рекурсия
    // *this = other;         // ✗ это тоже B::operator= → рекурсия
    return *this;
}
```

**Когда вызывается автоматический `operator=`:** при присваивании объектов, если правый операнд приводится к типу левого:

```cpp
class Point {
    int x, y;
public:
    Point(int x, int y) : x(x), y(y) {}
};

void demo() {
    Point p1(1, 1);
    Point p2(2, 2);

    p1 = p2;             // ✓ автоген. operator= (Point = Point)
    p1 = Point(3, 3);    // ✓ правый операнд — временный Point, приводится по типу

    // p1 = 5;           // ✗ для присваивания нужно преобразовать int -> Point,
    //                    //   но конструктора Point(int) нет → ошибка
}
```

## 11. Move-семантика. Правило пяти/нуля

**Перемещение** позволяет «украсть» ресурсы у временного объекта вместо дорогого копирования.

```cpp
class Buffer {
    int* data;
    int  size;
public:
    // Конструктор перемещения: забираем указатель у other, не копируя данные
    Buffer(Buffer&& other) noexcept {
        data = other.data;        // украли указатель
        size = other.size;
        other.data = nullptr;     // оставили other в "пустом", но валидном состоянии
        other.size = 0;
    }

    // Перемещающий оператор присваивания
    Buffer& operator=(Buffer&& other) noexcept {
        if (this != &other) {
            delete[] data;        // освободили своё
            data = other.data;    // забрали чужое
            size = other.size;
            other.data = nullptr;
            other.size = 0;
        }
        return *this;
    }

    ~Buffer() { delete[] data; }
};
```

**Когда выбирается перемещающая версия:** когда правый операнд — **rvalue** (временный объект или результат `std::move`):

```cpp
Buffer make();          // возвращает временный Buffer

void demo() {
    Buffer a, b;

    a = make();                 // make() — rvalue (временный) → move
    a = std::move(b);           // std::move превращает b в rvalue → move
    // (после std::move(b) объект b в "пустом" состоянии — больше им не пользуемся)

    Buffer c;
    Buffer d;
    c = d;                      // d — lvalue → COPY (не move)
}
```

Если перемещающего оператора **нет** (объявлен только копирующий), во всех случаях выбирается **копирующий** — перемещение не происходит никогда. `std::move` сам по себе ничего не перемещает — он лишь приводит выражение к rvalue, давая компилятору возможность выбрать move-перегрузку (если она есть).

**Правило пяти.** Если классу нужен хотя бы один из пяти специальных методов (деструктор, копирующий конструктор, копирующий `operator=`, перемещающий конструктор, перемещающий `operator=`) — скорее всего, нужны все пять, потому что это обычно означает владение ресурсом:

```cpp
class Resource {
public:
    ~Resource();                              // деструктор
    Resource(const Resource&);                // копирующий конструктор
    Resource& operator=(const Resource&);     // копирующий operator=
    Resource(Resource&&) noexcept;            // перемещающий конструктор
    Resource& operator=(Resource&&) noexcept; // перемещающий operator=
};
```

**Правило нуля.** Лучший вариант — спроектировать класс так, чтобы не писать ни один из них: использовать типы, которые сами управляют ресурсами (`std::string`, `std::vector`, умные указатели). Тогда сгенерированные версии корректны:

```cpp
#include <string>
#include <vector>

class Document {
    std::string title;          // сам управляет своей памятью
    std::vector<std::string> lines;
    // ничего из "пятёрки" писать не нужно — сгенерированные методы корректны
};
```

## 12. const-корректность

`void f() const;` — **константный метод**: обещает не изменять состояние объекта. Его можно вызывать для константных объектов.

```cpp
class Counter {
    int value;
public:
    int get() const {       // не меняет объект — помечен const
        return value;
    }
    void inc() {            // меняет объект — НЕ const
        ++value;
    }
};

void demo() {
    Counter c;
    c.inc();                // ✓
    c.get();                // ✓

    const Counter cc;
    cc.get();               // ✓ const-метод можно вызвать у const-объекта
    // cc.inc();            // ✗ неконстантный метод у const-объекта запрещён
}
```

**Тип `this`:**

- в обычном методе — `A* const` (указатель константный, объект изменяемый);
- в `const`-методе — `const A* const` (и объект const, и сам указатель const).

```cpp
class A {
    int m_a;
public:
    void normal()      {  this->m_a = 1;  }   // this имеет тип A* const — поле менять можно
    void constant() const {
        // this->m_a = 1;                      // ✗ this имеет тип const A* const — менять нельзя
        int copy = this->m_a;                  // ✓ читать можно
    }
};
```

**Перегрузка по const.** Можно иметь обе версии — выбор зависит от константности объекта:

```cpp
class Array {
    int data[100];
public:
    int& at(int i)             { return data[i]; }   // для неконстантных: можно менять
    const int& at(int i) const { return data[i]; }   // для константных: только чтение
};

void demo() {
    Array a;
    a.at(0) = 5;            // ✓ вызвалась неконстантная версия, можно присвоить

    const Array b = a;
    int x = b.at(0);       // ✓ вызвалась const-версия
    // b.at(0) = 5;        // ✗ const-версия вернула const int& — присвоить нельзя
}
```

Правила выбора: через `const`-объект/ссылку/указатель вызывается const-версия; через неконстантный — обычная; неконстантный метод нельзя вызвать у `const`-объекта.

**const с указателями** (читать справа налево):

```cpp
int x = 10, y = 20;

const int* p1 = &x;     // указатель на const int: *p1 менять нельзя, p1 — можно
p1 = &y;                // ✓ меняем сам указатель
// *p1 = 5;             // ✗ менять значение нельзя

int* const p2 = &x;     // const-указатель на int: p2 менять нельзя, *p2 — можно
*p2 = 5;                // ✓ меняем значение
// p2 = &y;             // ✗ менять указатель нельзя

const int* const p3 = &x;  // и то, и другое запрещено менять
```

## 13. static-члены и методы

**Статическое поле** — общее для всех объектов класса, существует в единственном экземпляре. Его нужно **объявить** в классе и **определить** вне класса:

```cpp
// header (объявление)
class Widget {
    static int count;          // ОБЪЯВЛЕНИЕ — память здесь не выделяется
public:
    Widget()  { ++count; }
    ~Widget() { --count; }
    static int howMany() { return count; }
};

// .cpp (определение — обязательно!)
int Widget::count = 0;

void demo() {
    std::cout << Widget::howMany();   // 0
    Widget a, b;
    std::cout << Widget::howMany();   // 2 — count общий для всех объектов
}
```

Если определение `int Widget::count = 0;` пропустить, ошибку выдаст **компоновщик (linker)** — «неопределённая ссылка»: компилятор о члене знает (видел объявление в классе), но физического объекта в программе нет.

**Статический метод** не привязан к объекту, не имеет `this`, может обращаться только к статическим членам. Вызывается через имя класса:

```cpp
class MathUtils {
    static int callCount;
public:
    static int square(int x) {     // статический метод
        ++callCount;               // ✓ доступ к статическому полю
        // return this->x;         // ✗ у статического метода нет this
        return x * x;
    }
};
int MathUtils::callCount = 0;

void demo() {
    int r = MathUtils::square(5);  // вызов без объекта: 25
}
```

Статическим методом **нельзя** реализовать перегрузку оператора-члена (оператору-члену нужен `*this` как левый операнд).

## 14. Битовые поля

**Битовое поле** задаёт точное число бит под поле — для экономии памяти и работы с аппаратными регистрами:

```cpp
struct Flags {
    unsigned ready    : 1;   // 1 бит
    unsigned mode     : 3;   // 3 бита (значения 0..7)
    unsigned reserved : 4;   // 4 бита
};                           // всё уместилось в 1 байт вместо 12

void demo() {
    Flags f;
    f.ready = 1;
    f.mode  = 5;             // ✓ читать и писать значение можно
}
```

**Ограничения** — к битовому полю **нельзя**:

```cpp
class A {
    int x : 8;               // битовое поле (8 бит)
public:
    void f() {
        x++;                          // ✓ изменять значение можно
        std::cout << x;               // ✓ читать можно

        // int* p = &x;               // ✗ нельзя взять адрес битового поля
        // int& r = x;                // ✗ нельзя создать ссылку на битовое поле
        // size_t n = sizeof(x);      // ✗ нельзя применить sizeof к битовому полю
    }
};
```

Причина запретов: битовое поле не обязано начинаться на границе байта и не имеет собственного адресуемого размера, поэтому адрес, ссылка и `sizeof` для него не определены.

## 15. Дружественные функции и классы (friend)

**`friend`** даёт функции или другому классу доступ к `private` и `protected` членам того класса, который объявил её другом.

```cpp
class Vector2 {
    double x, y;
public:
    Vector2(double x, double y) : x(x), y(y) {}

    // объявляем свободную функцию другом — она получит доступ к x, y
    friend double dot(const Vector2& a, const Vector2& b);
};

// определение друга — это обычная свободная функция (без Vector2:: и без friend)
double dot(const Vector2& a, const Vector2& b) {
    return a.x * b.x + a.y * b.y;     // ✓ доступ к private-полям обоих аргументов
}
```

**Свойства дружбы:**

- friend имеет доступ к закрытым членам **только того класса**, который его объявил;
- дружба **не наследуется** (друг базового класса не становится автоматически другом производного);
- дружба **не транзитивна** (друг моего друга — не мой друг);
- дружба **не взаимна** (если A объявил B другом, это не делает A другом B).

>![](imgs/1.gif)

**Тонкость с наследованием.** Если `F` — друг `B`, где `B : public A`, то `F` видит члены `B` (включая `private`-поля `B`) и унаследованные `protected`-члены `A`. Но `private`-члены `A` недоступны ни самому `B`, ни его другу `F`:

```cpp
class A {
    int m_x;                 // private в A
protected:
    int m_y;                 // protected в A
};

class B : public A {
    int m_b;                 // private в B
    friend void F(B& b);     // F — друг B
};

void F(B& b) {
    std::cout << b.m_b;      // ✓ m_b — private B, F друг B
    std::cout << b.m_y;      // ✓ m_y — protected A, унаследован в B, доступен другу B
    // std::cout << b.m_x;   // ✗ m_x — private A: недоступен ни B, ни другу B
}
```

**Зачем нужны.** Чаще всего — для перегрузки бинарных операторов, где левый операнд не объект класса (например, `operator<<` для вывода в поток):

```cpp
#include <iostream>

class Money {
    long cents;
public:
    Money(long c) : cents(c) {}
    friend std::ostream& operator<<(std::ostream& os, const Money& m);
};

std::ostream& operator<<(std::ostream& os, const Money& m) {
    return os << m.cents / 100 << '.' << m.cents % 100;   // доступ к private cents
}

void demo() {
    Money m(1050);
    std::cout << m;          // печатает 10.50; левый операнд — std::cout, не Money
}
```

## 16. Перегрузка операторов

Перегрузка позволяет задать поведение операторов для пользовательских типов.

**Общие правила:**

- операторы перегружаются **только для пользовательских типов** (поведение для встроенных менять нельзя);
- можно перегрузить **нестатическим public-методом** (левый операнд — `*this`) или **глобальной/`friend`-функцией**;
- статическим методом и protected-членом для внешнего взаимодействия объектов — нельзя/бессмысленно;
- семантика тела произвольна — компилятор не проверяет «смысл» (технически `operator+` может делать вычитание);
- **нельзя** перегрузить: `.` (точка), `.*`, `::`, `?:`, `sizeof`, `typeid`;
- `operator->`, `operator[]`, `operator()`, `operator=`, операторы сравнения, арифметику и т. п. — **можно**.

**Метод или глобальная функция?** Если левый операнд — объект нашего класса, подойдёт метод. Если левый операнд **не** нашего типа — нужна глобальная функция:

```cpp
class Complex {
    double re, im;
public:
    Complex(double re = 0, double im = 0) : re(re), im(im) {}

    // Вариант "метод": левый операнд — *this (объект Complex)
    Complex operator+(const Complex& rhs) const {
        return Complex(re + rhs.re, im + rhs.im);
    }

    friend Complex operator+(double left, const Complex& right);
};

// Вариант "глобальная функция": левый операнд — double (не Complex),
// поэтому методом класса это сделать нельзя
Complex operator+(double left, const Complex& right) {
    return Complex(left + right.re, right.im);
}

void demo() {
    Complex a(1, 2), b(3, 4);
    Complex c = a + b;       // вызывается метод Complex::operator+
    Complex d = 5.0 + a;     // вызывается глобальная функция (левый операнд double)
}
```

Ситуации, где глобальная функция **обязательна** (левый операнд чужой):

```cpp
std::cout << obj;    // левый операнд — std::ostream
result = 1 + obj;    // левый операнд — int
```

**Бинарный `operator+`** возвращает **новый объект по значению**:

```cpp
class A {
public:
    friend A operator+(const A&, const A&);    // ✓ возврат по значению

    // friend A operator+(const A&, const A&) const;  // ✗ у friend нет const
    // friend A& operator+(const A&, const A&);        // ✗ возврат ссылки на временный объект
};
```

Возврат `A&` для `+` некорректен: результат сложения — новый временный объект, ссылка на него стала бы висячей.

**Инкремент — префиксный и постфиксный:**

```cpp
class Counter {
    int value;
public:
    Counter(int v = 0) : value(v) {}

    Counter& operator++() {        // префиксный ++c: меняем себя и возвращаем ссылку
        ++value;
        return *this;
    }

    Counter operator++(int) {      // постфиксный c++: фиктивный параметр int
        Counter old = *this;       // сохраняем старое значение
        ++value;                   // увеличиваем себя
        return old;                // возвращаем СТАРОЕ значение ПО ЗНАЧЕНИЮ
    }
};

void demo() {
    Counter c(5);
    Counter a = ++c;   // префиксный: c стал 6, a == 6
    Counter b = c++;   // постфиксный: b == 6 (старое), c стал 7
}
```

Правильные сигнатуры: префиксный — `A& operator++()` (возврат ссылки), постфиксный — `A operator++(int)` (параметр-заглушка `int`, возврат по значению). Комбинации `A operator++()` или `A& operator++(int)` некорректны по смыслу.

**`operator->`** вызывается, когда `->` применяют к **объекту** класса (не к настоящему указателю):

```cpp
class A {
public:
    A* operator->() { return this; }
    void f() {}
};

void demo() {
    A a;
    a->f();             // a — ОБЪЕКТ → вызывается A::operator->(), затем ->f() у результата
    a.f();              // обычный вызов, operator-> не задействован

    A* p = new A;
    p->f();             // p — НАСТОЯЩИЙ указатель → operator-> класса НЕ вызывается
    delete p;
}
```

## 17. Наследование

**Наследование** создаёт новый класс (производный) на основе существующего (базового):

```cpp
class Animal {
protected:
    std::string name;
public:
    Animal(const std::string& n) : name(n) {}
    void eat() { std::cout << name << " eats\n"; }
};

class Dog : public Animal {        // Dog наследует Animal публично
    std::string breed;
public:
    Dog(const std::string& n, const std::string& b)
        : Animal(n), breed(b)      // инициализируем базовую часть
    {}
    void bark() { std::cout << name << " barks\n"; }  // name унаследован (protected)
};

void demo() {
    Dog d("Rex", "Husky");
    d.eat();        // ✓ унаследованный метод
    d.bark();       // ✓ собственный метод
}
```

**Виды наследования** (по модификатору):

- **public** — моделирует отношение **«является» (is-a)**; публичный интерфейс базового остаётся публичным;
- **protected** — публичные и защищённые члены базового становятся защищёнными;
- **private** — всё унаследованное становится приватным (моделирует «реализовано через», а не «является»).

**Открытое (public) наследование** подчиняется **принципу подстановки Барбары Лисков**: производный объект должен быть пригоден везде, где ожидается базовый. Отсюда корректные формулировки:

- всё, что справедливо для базового класса, должно быть применимо и к производному;
- везде, где требуется объект базового класса, можно использовать объект производного;
- производный класс добавляет специфику к базовой функциональности.

```cpp
void feed(Animal& a) {     // функция работает с любым Animal
    a.eat();
}

void demo2() {
    Dog d("Rex", "Husky");
    feed(d);               // ✓ Dog подставляется вместо Animal (принцип Лисков)
}
```

**Доступ при наследовании:**

- `private`-члены базового — **недоступны** в производном;
- `protected` — доступны в производном (и его друзьях);
- `public` — доступны всем.

**Срезка (object slicing):** при передаче/присваивании производного объекта **по значению** туда, где ожидается базовый, производная часть теряется:

```cpp
void byValue(Animal a) {   // принимает по ЗНАЧЕНИЮ
    a.eat();               // работает только с Animal-частью
}

void demo3() {
    Dog d("Rex", "Husky");
    byValue(d);            // в a скопируется только Animal-часть d — breed потерян (срезка)

    Animal a = d;          // то же самое: a содержит лишь Animal-часть
}
```

## 18. Виртуальные функции и полиморфизм

**Виртуальная функция** (`virtual`) обеспечивает **позднее (динамическое) связывание**: какой метод вызвать, определяется по **фактическому типу объекта** во время выполнения, а не по типу указателя/ссылки на этапе компиляции.

```cpp
class Shape {
public:
    virtual double area() const { return 0; }   // виртуальная
};

class Circle : public Shape {
    double r;
public:
    Circle(double r) : r(r) {}
    double area() const override {               // переопределение
        return 3.14159 * r * r;
    }
};

class Square : public Shape {
    double side;
public:
    Square(double s) : side(s) {}
    double area() const override {
        return side * side;
    }
};

void printArea(const Shape& s) {     // принимает любой Shape по ссылке
    std::cout << s.area() << '\n';   // вызовется area() ФАКТИЧЕСКОГО типа
}

void demo() {
    Circle c(2);
    Square sq(3);
    printArea(c);    // 12.566 — вызвался Circle::area()
    printArea(sq);   // 9       — вызвался Square::area()
}
```

**Механизм (vtable / vptr).** Если в классе есть хотя бы одна виртуальная функция:

- компилятор создаёт **таблицу виртуальных функций (vtable)** — **одну на класс** (для базового и для каждого производного отдельная таблица);
- в каждый объект добавляется **указатель на vtable (`vptr`)** — служебное поле.

Таблица — одна на класс, а не на каждый объект; объект лишь хранит указатель на таблицу своего класса.

**Полиморфный вызов** возможен через **указатель или ссылку** на базовый класс. Через объект по значению полиморфизма нет:

```cpp
class A {
public:
    virtual void f() { std::cout << "A::f\n"; }
};
class B : public A {
public:
    void f() override { std::cout << "B::f\n"; }
};

void demo() {
    B b;

    A* p = &b;   p->f();   // B::f — через указатель, полиморфно
    A& r = b;    r.f();    // B::f — через ссылку, полиморфно

    A  copy = b; copy.f(); // A::f — копия по значению (срезка), вызов статический
    b.f();                 // B::f — тип известен на компиляции
}
```

**Ключевые случаи, которые часто проверяют:**

**1. Метод не virtual.** Вызов связывается статически по типу указателя/ссылки:

```cpp
class A { public: void F() { std::cout << "A::F\n"; } };          // НЕ virtual
class B : public A { public: virtual void F() { std::cout << "B\n"; } };
class C : public B { public: void F() override { std::cout << "C\n"; } };

void demo() {
    A* p = new C;
    p->F();        // выведет "A::F": в точке вызова через A* функция F НЕВИРТУАЛЬНА,
                   // поэтому связывание статическое по типу A
    delete p;
}
```

**2. Virtual, но не переопределена** в производном — вызовется унаследованная версия базового:

```cpp
class A { public: virtual void VF() { std::cout << "A::VF\n"; } };
class B : public A { /* VF не переопределена */ };

void demo() {
    A* p = new B;
    p->VF();       // выведет "A::VF": B не переопределил VF, используется версия A
    delete p;
}
```

## 19. Абстрактные классы и чисто виртуальные функции

**Чисто виртуальная функция** не имеет реализации в базовом классе:

```cpp
class Shape {
public:
    virtual double area() const = 0;     // = 0 делает функцию чисто виртуальной
    virtual void   draw() const = 0;
    virtual ~Shape() {}                  // деструктор виртуальный (см. раздел 20)
};
```

Класс, содержащий хотя бы одну чисто виртуальную функцию, является **абстрактным** — создать его объект **нельзя**:

```cpp
void demo() {
    // Shape s;             // ✗ ошибка компиляции — абстрактный класс
    // Shape* p = new Shape; // ✗ тоже ошибка
}
```

Производный класс становится конкретным (создаваемым), только если **переопределит все** унаследованные чисто виртуальные функции:

```cpp
class Circle : public Shape {
    double r;
public:
    Circle(double r) : r(r) {}
    double area() const override { return 3.14159 * r * r; }
    void   draw() const override { std::cout << "circle\n"; }
    // обе чисто виртуальные функции переопределены → Circle конкретный
};

class Partial : public Shape {
public:
    double area() const override { return 0; }
    // draw() НЕ переопределена → Partial остаётся абстрактным
};

void demo2() {
    Circle c(2);            // ✓ Circle конкретный
    // Partial p;          // ✗ Partial абстрактный: draw() не реализована
}
```

Если базовый класс объявляет `virtual void f() = 0;`, а производный не переопределяет её, то попытка `new Производный` — **ошибка компиляции**. Абстрактные классы задают **интерфейс**, который обязаны реализовать наследники.

## 20. Виртуальный деструктор

Если объект производного класса удаляется через указатель на базовый, поведение зависит от того, виртуален ли деструктор базового.

**Невиртуальный деструктор — проблема:**

```cpp
class A {
public:
    ~A() { std::cout << "~A\n"; }        // НЕ virtual
};
class B : public A {
    int* data;
public:
    B()  { data = new int[100]; }
    ~B() { delete[] data; std::cout << "~B\n"; }
};

void demo() {
    A* p = new B;
    delete p;        // выведет только "~A" — ~B() НЕ вызовется!
                     // data не освобождён → УТЕЧКА памяти
}
```

**Виртуальный деструктор — правильно:**

```cpp
class A {
public:
    virtual ~A() { std::cout << "~A\n"; }   // virtual
};
class B : public A {
    int* data;
public:
    B()  { data = new int[100]; }
    ~B() { delete[] data; std::cout << "~B\n"; }
};

void demo() {
    A* p = new B;
    delete p;        // выведет "~B" затем "~A" — оба деструктора, память освобождена
}
```

**Правило:** если класс предполагается использовать полиморфно (как базовый с виртуальными методами), его деструктор должен быть **виртуальным**. Порядок вызова при `delete` через базовый указатель с виртуальным деструктором: сначала `~B()`, затем `~A()` (обратный конструированию).

## 21. RTTI: dynamic_cast и typeid. Приведения типов

**RTTI (Run-Time Type Information)** — информация о типах во время выполнения; работает для полиморфных типов (с виртуальными функциями).

**`dynamic_cast`** выполняет безопасное приведение по иерархии на этапе **выполнения**:

```cpp
class A { public: virtual ~A() {} };
class B : public A { public: void special() {} };
class C : public A {};

void process(A* p) {
    // Пытаемся привести к B*. Если фактический тип не B — вернётся nullptr.
    B* pb = dynamic_cast<B*>(p);
    if (pb) {
        pb->special();       // безопасно: точно объект B
    }
}

void demo() {
    A* p1 = new B;
    process(p1);             // pb != nullptr → special() вызовется

    A* p2 = new C;
    process(p2);             // pb == nullptr → special() пропустится

    delete p1;
    delete p2;
}
```

- нисходящее приведение (база → производный) проверяется в рантайме; при неудаче для указателей возвращается `nullptr`, для ссылок бросается `std::bad_cast`;
- восходящее приведение (производный → база) всегда корректно и выполняется неявно.

Для иерархии `A ← B ← C` (где C наследует B, B наследует A):

```cpp
class A { public: virtual ~A() {} };
class B : public A {};
class C : public B {};

void demo() {
    A* p1 = new C;
    C* c1 = dynamic_cast<C*>(p1);   // ✓ фактический тип C — успех
    B* b1 = dynamic_cast<B*>(p1);   // ✓ C является B — успех

    A* p2 = new B;
    C* c2 = dynamic_cast<C*>(p2);   // nullptr: объект только B, не C

    C* obj = new C;
    A* up = obj;                    // ✓ восходящее приведение неявно, без cast

    delete p1;
    delete p2;
    delete obj;
}
```

**`typeid`** возвращает информацию о **фактическом** типе:

```cpp
#include <typeinfo>

class A { public: virtual ~A() {} };
class B : public A {};
class C : public B {};

void check(A& r) {
    if (typeid(r) == typeid(B)) {       // истинно только если фактический тип РОВНО B
        std::cout << "это ровно B\n";
    }
}

void demo() {
    A a;
    B b;
    C c;
    check(a);   // typeid(a) == A → ложь
    check(b);   // typeid(b) == B → ИСТИНА
    check(c);   // typeid(c) == C → ложь (C, а не B)
}
```

Условие `typeid(r) == typeid(B)` истинно, только если фактический тип объекта — **ровно `B`** (не `A` и не производный от `B` тип `C`).

**Другие приведения (для полноты):**

```cpp
double d = 3.9;
int i = static_cast<int>(d);            // 3 — проверяется на компиляции

const int ci = 10;
int* p = const_cast<int*>(&ci);         // снятие const (использовать осторожно)

long addr = reinterpret_cast<long>(p);  // переинтерпретация битов (низкоуровнево, опасно)
```

- **`static_cast`** — приведения, проверяемые на компиляции (числовые, вверх по иерархии, явные преобразования); без проверки в рантайме;
- **`const_cast`** — снятие/добавление `const`;
- **`reinterpret_cast`** — низкоуровневая переинтерпретация битов;
- C-style cast `(T)x` — выбирает одно из вышеперечисленных, менее безопасен и не рекомендуется.

## 22. Обработка исключений

Механизм исключений построен на трёх **ключевых словах**: **`try`**, **`throw`**, **`catch`**. (`exception` — это **класс** стандартной библиотеки `std::exception`, а не ключевое слово.)

```cpp
#include <stdexcept>

double divide(int a, int b) {
    if (b == 0) {
        throw std::runtime_error("деление на ноль");   // выброс исключения
    }
    return static_cast<double>(a) / b;
}

void demo() {
    try {
        double r = divide(10, 0);
        std::cout << r;
    }
    catch (const std::runtime_error& e) {   // ловим конкретный тип
        std::cout << "ошибка: " << e.what() << '\n';
    }
}
```

**Выбор обработчика.** Блоки `catch` просматриваются **по порядку**; срабатывает **первый подходящий по типу**. Для иерархии `B : public A`:

```cpp
class A {};
class B : public A {};

void demo() {
    try {
        throw B();
    }
    catch (A& a) {
        std::cout << "поймал как A\n";   // СРАБОТАЕТ ЭТОТ: B является A
    }
    catch (B& b) {
        std::cout << "поймал как B\n";   // недостижим — перехвачен выше
    }
    catch (...) {
        std::cout << "поймал всё\n";     // сюда не дойдёт
    }
}
```

Поэтому **более производные типы перечисляют раньше** базовых, иначе обработчик базового «перехватит» всё. Правильный порядок:

```cpp
try {
    throw B();
}
catch (B& b) { /* сначала самый производный */ }
catch (A& a) { /* потом базовый */ }
catch (...)  { /* в конце — ловит всё остальное */ }
```

**Раскрутка стека (stack unwinding):** при выбросе исключения автоматически вызываются деструкторы всех локальных объектов между `throw` и поймавшим `catch` — это обеспечивает освобождение ресурсов:

```cpp
void risky() {
    Buffer local(100);     // локальный объект
    throw std::runtime_error("oops");
    // при выбросе ~Buffer() для local вызовется автоматически (раскрутка стека)
}
```

## 23. Раздельная компиляция (.h / .cpp)

Программа на C++ обычно разбивается на заголовочные файлы (`.h`) и файлы реализации (`.cpp`):

- в **`.h`** — объявление класса, прототипы методов, inline-методы;
- в **`.cpp`** — реализации методов с квалификацией класса.

```cpp
// ---------- A.h ----------
#pragma once                    // защита от повторного включения

class A {
    int m_a;
public:
    A(int a);
    void f(int value);          // прототип — реализация в A.cpp
    int get() const { return m_a; }   // inline-метод прямо в заголовке
};

// ---------- A.cpp ----------
#include "A.h"

A::A(int a) : m_a(a) {}         // обязательно A:: перед именем

void A::f(int value) {          // обязательно A:: — иначе это свободная функция
    m_a       = value;          // ✓ к полю можно так
    this->m_a = value;          // ✓ или так (this — указатель, через ->)
    A::m_a    = value;          // ✓ или так (квалификация поля текущего объекта)
}
```

Внутри метода `this` — указатель, поэтому `this->m_a` (а не `this.m_a`). Свободная функция без `A::` методом класса не является и доступа к полям не имеет:

```cpp
void f(int value) {             // нет A:: → это НЕ метод A, а свободная функция
    // m_a = value;             // ✗ ошибка: m_a здесь не существует
}
```

Статические члены **определяются** в `.cpp` (см. раздел 13). Заголовки защищают от повторного включения через `#pragma once` или include guard (`#ifndef/#define/#endif`).

## 24. Время жизни и области видимости объектов

**Категории времени жизни:**

- **автоматическое** (локальные переменные) — живут от объявления до конца блока;
- **статическое** (глобальные, `static`) — живут всю программу;
- **динамическое** (`new`/`delete`) — управляется вручную.

**Инициализация по умолчанию:**

- глобальные и `static` объекты встроенных типов **обнуляются** (zero-initialization);
- локальные объекты встроенных типов **не инициализируются** (содержат мусор).

```cpp
class A { public: int m_a; };   // m_a — встроенный тип, без инициализатора

A a1;                           // ГЛОБАЛЬНЫЙ → m_a == 0
namespace { A a2; }             // в анонимном namespace → m_a == 0

int main() {
    A a3;                       // ЛОКАЛЬНЫЙ → m_a НЕ инициализирована (мусор)
    static A a4;                // static → m_a == 0
}
```

**Типичные ошибки с временем жизни:**

```cpp
class A { public: void f() {} };

// ① адрес временного объекта — нельзя
void err1() {
    // A* p = &A();             // ✗ нельзя взять адрес временного объекта
}

// ② висячий указатель: объект уничтожен, а указатель используется
void err2() {
    A* pa;
    {
        A a;
        pa = &a;                // pa указывает на локальный a
    }                           // a уничтожен здесь (конец блока)
    // pa->f();                 // ✗ обращение к мёртвому объекту — UB
}

// ③ возврат ссылки на локальный объект — висячая ссылка
A& err3() {
    A local;
    return local;               // ✗ local уничтожится при выходе — ссылка повиснет
}

// ✓ корректные варианты
void ok() {
    A* p = new A;               // объект в куче живёт до delete
    p->f();
    delete p;

    {
        A a;                    // локальный объект — корректен в пределах блока
        a.f();
    }
}
```

## 25. Вложенные классы

Класс можно объявить внутри другого класса:

```cpp
class List {
    struct Node {               // вложенный класс
        int value;
        Node* next;
        Node(int v);            // конструктор объявлен, определим вне
    };

    Node* head = nullptr;
public:
    void push(int v);
};
```

Вложенный класс находится в **области видимости** внешнего, поэтому вне классов его методы определяются с полной квалификацией:

```cpp
// конструктор вложенного класса: нужна полная квалификация List::Node::Node
List::Node::Node(int v) : value(v), next(nullptr) {}      // ✓

// Node::Node(int v) { ... }      // ✗ имя Node вне List не видно

void List::push(int v) {
    Node* n = new Node(v);        // ✓ внутри List имя Node видно без квалификации
    n->next = head;
    head = n;
}
```

Аналогично с конструкторами на примере `Out`/`In`:

```cpp
class Out {
    class In {
    public:
        In();
    };
public:
    Out();
};

Out::Out() {}                     // ✓
Out::In::In() {}                  // ✓ — In квалифицируется через Out
// In::In() {}                    // ✗ — имя In вне Out не видно
```

Вложенный класс имеет доступ к статическим членам и типам внешнего класса, но не к нестатическим полям конкретного объекта внешнего класса (если ему не передать ссылку или указатель на этот объект).

### Q1. Дружественный метод другого класса (доступ к private)

```cpp
class X {
    int m_x;
    void fX(Y& y);
    friend void Y::fY1(X& x);
};
class Y {
    int m_y;
    void fY1(X& x);
    void fY2(X& x);
};
```
**Отметьте корректные варианты:**

- **a) `void Y::fY2(X& x) { x.m_x++; }`** — ✗
  `fY2` обращается к `x.m_x`, а `m_x` — приватное поле `X`. Другом `X` объявлен только `Y::fY1`, но **не** `fY2`. Дружба адресная: она даётся конкретной функции, а не всему классу `Y`. Значит `fY2` доступа к `m_x` не имеет → ошибка компиляции.
- **b) `void X::fX(Y& y) { y.m_y++; }`** — ✗
  Здесь метод класса `X` лезет в `y.m_y` — приватное поле **чужого** класса `Y`. `X` не объявлен другом `Y`, поэтому доступа к `m_y` нет. (То, что `fX` — метод `X`, даёт доступ к приватным полям `X`, но не `Y`.)
- **c) `void Y::fY1(X& x) { x.m_x++; }`** — ✓
  `fY1` — это именно та функция, которую `X` объявил своим другом (`friend void Y::fY1(X& x);`). Поэтому она имеет полный доступ к приватным членам `X`, включая `m_x`.

**Ответ: c.**

### Q2. Тип указателя `this` в обычном методе

```cpp
class A {
    // ...
    const int* f();
};
```
**Тип указателя `this` в методе `f`:** `A* const` / `void*` / `A const*` / `const A*` / `A*` / `const A* const`.

Метод `f` **не** помечен `const`, значит через `this` объект можно изменять. Сам указатель `this` всегда константен (его нельзя перенаправить на другой объект). Поэтому тип — указатель на изменяемый `A`, но сам указатель `const`:

- **`A* const`** — ✓ изменяемый объект (`A`), константный указатель (`const` справа). Это и есть `this` в обычном методе.
- **`const A*` / `A const*`** — ✗ это «указатель на const A»: запрещало бы менять объект, но `f` не const, объект менять можно. К тому же это варианты-синонимы между собой.
- **`const A* const`** — ✗ это тип `this` в **const-методе**, а `f` не const.
- **`A*`** — ✗ формально указатель на изменяемый `A`, но упущено, что сам `this` константен (нельзя `this = ...`). Точный тип включает `const` после звёздочки.
- **`void*`** — ✗ `this` всегда типизирован конкретным классом, а не `void*`.

Тип возвращаемого значения `const int*` к типу `this` отношения не имеет — это просто что возвращает функция.

**Ответ: `A* const`.**

### Q3. Невиртуальный... нет — виртуальный метод, не переопределённый в B

```cpp
class A { public: virtual void VF() { } };
class B : public A { /* метод VF() не перегружен */ };
int main() {
    A* pA = new B;
    pA->VF();
}
```
**Метод VF какого класса будет вызван?** (Ошибка компиляции / Ошибка выполнения / A / B)

`VF` — виртуальная, значит вызов разрешается динамически по фактическому типу объекта (`B`). Но `B` **не переопределяет** `VF`, поэтому в таблице виртуальных функций `B` остаётся унаследованная запись — указатель на `A::VF`.

- **Ошибка компиляции** — ✗ код корректен: `B` создаётся (не абстрактный), `VF` есть.
- **Ошибка выполнения** — ✗ всё определено, никакого UB нет.
- **A** — ✓ так как `B` не дал своей версии, динамический вызов попадает в унаследованную `A::VF()`.
- **B** — ✗ у `B` нет собственной `VF`, переопределения не было.

**Ответ: A.**

### Q4. dynamic_cast по иерархии A←B←C

```cpp
class A { virtual void f(); /* ... */ };
class B : public A { /* ... */ };
class C : public B { /* ... */ };
```
**В каких вариантах будет сформирован корректный указатель `pp`?**

- **a) `A* p = new C; C* pp = dynamic_cast<C*>(p);`** — ✓
  Фактический объект — `C`. Приводим `A*` к `C*` вниз по иерархии; так как реальный тип действительно `C`, проверка в рантайме проходит, `pp` указывает на валидный объект.
- **b) `A* p = new C; B* pp = dynamic_cast<B*>(p);`** — ✓
  Объект `C` «является» и `B` (так как `C : B`). Приведение к промежуточному `B*` успешно, `pp` корректен.
- **c) `A* p = new B; C* pp = dynamic_cast<C*>(p);`** — ✗
  Фактический объект — только `B`, а пытаемся привести к `C*` (более производный, чем есть). `B` не является `C`. `dynamic_cast` для указателя вернёт **`nullptr`** → корректного указателя нет.
- **d) `B* p = new C; A* pp = p;`** — ✓
  Это восходящее приведение `B* → A*` (производный → базовый), оно всегда корректно и выполняется **неявно**, даже без `dynamic_cast`. `pp` валиден.

**Ответ: a, b, d.**

### Q5. Инициализация встроенного объекта в списке инициализации

```cpp
class A { int m_a; public: A(int a = 0); };
class B { int m_b; A m_A; public: B(const A&, int b); };
```
**Корректные и эффективные варианты инициализации встроенного объекта `m_A`:**

- **a) `B::B(const A& ra, int b) { m_A = ra; }`** — ✗ (точнее, неэффективно)
  Здесь `m_A` сначала создаётся конструктором по умолчанию `A(0)`, а затем в теле перезаписывается оператором присваивания. Это не инициализация, а «создание + присваивание» — двойная работа. Вопрос требует **корректный И эффективный** способ, этот неэффективен.
- **b) `B::B(const A& ra, int b) : m_A(ra.m_a) {}`** — ✗
  `ra.m_a` — обращение к **приватному** полю `m_a` класса `A` из класса `B`. `B` не друг `A` и не наследник → нет доступа к `m_a`. Ошибка компиляции.
- **c) `B::B(const A& ra, int b) : m_A(ra) {}`** — ✓
  `m_A` инициализируется в списке инициализации копией `ra` (вызывается конструктор копирования `A`). Это и корректно (доступ к приватным полям не нужен), и эффективно (один шаг, без лишнего присваивания).

**Ответ: c.**

### Q6. Корректные реализации метода в .cpp

```cpp
// A.h
class A { int m_a; public: void f(int); };
```
**Корректные варианты A.cpp:**

- **a) `void A::f(int a) { this->m_a = a; }`** — ✓
  `this` — указатель на текущий объект, доступ к полю через `->`. Корректно.
- **b) `void A::f(int a) { (*this)->m_a = a; }`** — ✗
  `*this` — это уже сам объект `A` (не указатель). К объекту нельзя применять `->`. Нужно было бы `(*this).m_a`. Ошибка компиляции.
- **c) `void A::f(int a) { m_a = a; }`** — ✓
  Неуточнённое `m_a` внутри метода — это поле текущего объекта. Корректно.
- **d) `void f(int a) { m_a = a; }`** — ✗
  Нет квалификации `A::`, поэтому это **свободная функция** `f`, а не метод класса `A`. В ней нет ни `this`, ни поля `m_a` → ошибка.
- **e) `void A::f(int a) { A::m_a = a; }`** — ✓
  `A::m_a` внутри метода — квалифицированное обращение к полю текущего объекта (эквивалентно `this->A::m_a`). Корректно.

**Ответ: a, c, e.**

### Q7. Полиморфный вызов виртуального метода

```cpp
class A { public: virtual void f(); };
class B : public A { public: virtual void f(); };
```
**В каких случаях компилятор генерирует полиморфный вызов метода `f`?**

- **a) `A* p = new A; p->f();`** — ✓
  Вызов через указатель → задействуется механизм виртуального вызова (через vtable). Фактический объект `A`, вызовется `A::f`. Это полиморфный вызов по механизму.
- **b) `B b; b.f();`** — ✗
  Вызов у объекта **по значению**: тип `b` точно известен на компиляции (`B`), компилятор делает прямой (статический) вызов `B::f`, vtable не нужен.
- **c) `B* p = new B; p->f();`** — ✓
  Вызов через указатель → виртуальный механизм; вызовется `B::f`.
- **d) `A* p = new B; p->f();`** — ✓
  Классический полиморфизм: указатель базового типа, объект производного. Через vtable вызовется `B::f`. Именно здесь динамическое связывание особенно наглядно.

Полиморфный (динамический) вызов запускается при обращении через **указатель или ссылку** — это a, c, d. В b — статический вызов по значению.

**Ответ: a, c, d.**

### Q10. Выбор catch-обработчика

```cpp
class A { /* ... */ };
class B : public A { /* ... */ };
int main() {
    try { /* ... */ throw B(); }
    catch (A& a) { /* */ }
    catch (B& b) { /* */ }
    catch (...)  { /* */ }
}
```
**Какой обработчик будет вызван?**

- **`catch (A& a)`** — ✓

- **`catch (B& b)`** — ✗ (недостижим)

- **`catch (...)`** — ✗
  Срабатывает только если ничего выше не подошло; здесь подошёл первый же.

**Ответ: `catch (A& a)`.**

### Q12. typeid и фактический тип

```cpp
class A { virtual void f(); };
class B : public A { };
class C : public B { };
void f(A& r) { if (typeid(r) == typeid(B)) { } }
```
**В каких случаях условие будет true?**

- **a) `A a; f(a);`** — ✗
  Фактический тип — `A`, `typeid(r)` == `typeid(A)` ≠ `typeid(B)`.
- **b) `C c; f(c);`** — ✗
  Фактический тип — `C`. `typeid` даёт **точный** тип, а `C` ≠ `B` (хотя `C` и наследует `B`). Условие ложно.
- **c) `B b; f(b);`** — ✓
  Фактический тип ровно `B`, `typeid(r)` == `typeid(B)` → true.

Важно: `typeid` сравнивает **точное** совпадение типа, а не «является ли». Поэтому даже потомок `C` не даёт true.

**Ответ: c.**

### Q37. Корректные вызовы функций f1(A,A) и f2(B,B)

- **A** — ✗ у чисто виртуальной нет тела в `A` (точнее, до вызова дело не дойдёт — не скомпилируется).
- **B** — ✗ `B` не переопределил `VF`, и объект `B` создать нельзя.
- **Ошибка выполнения** — ✗ ошибка раньше — на этапе компиляции.

**Ответ: Ошибка при компиляции.**

### Q66. Конструктор класса B — как инициализировать поле базового

```cpp
class A { int m_a; public: A(int a) { m_a = a; } };
class B : public A { public: B(int a, int b); };
```
**Как в конструкторе B проинициализировать поле m_a базового класса?**

- **a) `B::B(int a, int b) : m_a(a) {}`** — ✗ нельзя инициализировать **поле** базового напрямую в списке производного; в списке можно указывать только сам базовый класс или свои поля.
- **b) `B::B(int a, int b) { m_a = a; }`** — ✗ `m_a` — приватное поле `A`, недоступно из `B`. Плюс у `A` нет конструктора по умолчанию, поэтому базовая часть и так не сможет проинициализироваться неявно.
- **c) `B::B(int a, int b) { A(a); }`** — ✗ это создаёт безымянный **временный** объект `A`, а базовую часть `B` не инициализирует. (И снова проблема с отсутствием конструктора по умолчанию у `A`.)
- **d) `B::B(int a, int b) : A(a) {}`** — ✓ правильный способ: вызвать конструктор базового класса `A(a)` в списке инициализации. Он и проинициализирует `m_a` внутри `A`.

**Ответ: d.**

### Q67. Move operator= НЕ вызывается

```cpp
class A { public: A(); A& operator=(const A&); /* других operator= нет */ };
```
Перемещающего оператора **нет** — только копирующий. Значит move не вызывается **никогда**: для любого правого операнда выбирается копирующий `operator=`.

- **a) Будет сгенерирована ошибка при компиляции** — ✗ ошибки нет: при отсутствии move просто используется copy.
- **b) `A a1, a2; a1 = a2;`** — ✓ здесь move не вызывается (это copy для lvalue) — то есть утверждение «move НЕ вызывается» верно.
- **c) `A a1, a2; a1 = std::move(a2);`** — ✓ хотя `std::move` даёт rvalue, move-оператора нет → подбирается copy. Move не вызывается → верно.
- **d) `A a1; a1 = A();`** — ✓ `A()` — rvalue, но move-оператора нет → снова copy. Move не вызывается → верно.

Вопрос «в каких случаях move НЕ вызывается» — поскольку его нет вообще, подходят все реальные присваивания.

**Ответ: b, c, d.**

### Q77. friend-функция и доступ при наследовании

```cpp
class A {
    int m_x;          // private
protected:
    int m_y;          // protected
};
class B : public A {
    int m_b;          // private
    friend void F(B& b);
};
```
`F` — друг `B` (но не `A`).

- **a) `void F(B& b) { std::cout << b.m_y; }`** — ✓
  `m_y` — `protected` в `A`, унаследован в `B`. Друг `B` (`F`) имеет доступ к членам `B`, включая унаследованные protected. Доступ есть.
- **b) `void F(B& b) { std::cout << b.m_b; }`** — ✓
  `m_b` — приватное поле `B`. `F` — друг `B` → видит его приватные члены.
- **c) `void F(B& b) { std::cout << b.m_x; }`** — ✗
  `m_x` — **приватное** поле `A`. К приватным членам `A` не имеет доступа ни сам `B`, ни его друг `F` (дружба `B` не распространяется на приватные части `A`).

**Ответ: a, b.**
